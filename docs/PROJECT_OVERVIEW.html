PERSONAL RESEARCH · V2

AI Game Testing System
基于《植物大战僵尸》的 AI 游戏试玩测试框架

基于 pypvz 原有战斗设计与素材，已构建白天实验版 V2。真人与 AI 共用动作执行逻辑，在固定规则、时间步和环境安排下记录对局，支持回放校验、整局比较及同局面决策比较；后续通过内容注册、参数配置和独立数据模块扩展实验。

核心对象Human Playtester ↔ AI Agent
实验载体pypvz · 白天实验版 V2
系统中心GameSession · 统一实验控制
研究目标评估 AI 替代部分真人试玩测试的可行性

01 · 项目定义

重点不是“让 AI 会玩 PvZ”，而是建立一套可比较的人机试玩测试机制。
核心研究问题：在相同游戏状态和测试条件下，AI Agent 产生的决策与行为轨迹，是否能够在足够程度上逼近真人试玩测试者，从而承担部分游戏策略、难度与关卡行为测试任务？
传统流程

真人试玩测试

招募玩家 → 完成关卡 → 记录策略与失败点 → 人工分析关卡体验和难度。

目标流程

AI 代理测试

AI 读取经过过滤的公开观察 → 通过共用动作接口游玩 → 自动产生结构化轨迹。真人仍通过画面感知，不宣称两者视觉体验相同。

最终比较

Human–AI Consistency

比较结果、策略、资源配置、动作选择、响应时机与整局行为轨迹的一致性。

02 · 系统总体架构

当前是模块化重构：game 负责战斗，daylab 负责实验控制、观察、记录和界面；不是只在原版外面套薄接口。

03 · 核心模块与职责

模块按职责拆分；原版入口已退役，扩展优先使用配置与注册，不建设通用插件平台。
INPUT

UI Input

daylab/ui：记录原始输入，点击格子时提交种植或铲除命令。选卡、取消属于界面行为；阳光自动收集。

INPUT

AI Connector

daylab/controllers：规则 AI 与兼容 Chat Completions 的云端连接器读取公开观察及近期历史。云端请求异步执行，不阻塞游戏。

CORE

Action Executor

daylab/actions + economy：共用种植、铲除、等待动作，统一检查资源、冷却、占用、去重与频率；验证失败不扣费。

CORE

Observation

daylab/observation：仅导出公开信息。精确血量、内部计时器和未来出怪另存内部检查点，不提供给 AI。

DATA

Logger & Replay

daylab/recording + replay：记录动作、事件和内部检查点；用已存环境安排及提交时刻从开局重放，校验状态差异。

CONTROL

Experiment Manager

daylab/session + config + reports：管理配置、种子和生命周期，以 20ms 固定步推进，导出 CSV 与本地 HTML 比较报告。

04 · 统一数据模型与接口

本地 Python 接口由 GameSession 提供；真人输入和 AI 决策共用 submit，暂无 HTTP 服务。

Observation · 公开观察（字段节选）

{ "observation_id": "episode-id:1620", "tick": 1620, "sim_ms": 32400, "status": "running", "sun": 175, "wave": 1, "plants": [ {"id":"plant-id","type":"SunFlower","row":2,"col":3} ], "zombies": [ {"id":"zombie-id","type":"Zombie","row":2,"x":650} ], "cards": [ {"plant_type":"Peashooter","cost":100, "ready":false,"cooldown_ms":3200} ] }

Action · 标准动作

{ "type": "PLACE_PLANT", "plant_type": "Peashooter", "row": 3, "col": 4 } 另两种动作： {"type":"REMOVE_PLANT","plant_id":"plant-id"} {"type":"WAIT"} 行列从 0 开始；铲除绑定实体 ID。 阳光自动入账，没有 COLLECT_SUN 动作。 submit 另传 observation_id 和 command_id。 返回接收状态，执行结果通过事件读取。

上例仅展示部分字段，不是完整协议；完整观察还包含地图、可见动作状态、子弹及小推车。AI 不获得精确血量、内部攻击计时器或未来出怪。

接口职责使用边界
observe() / public_context()公开观察 / 规则、观察及最近五秒历史不含精确血量与未来事件
submit(action, observation_id, command_id)提交标准动作，统一校验、去重并排队默认每 200ms 最多一次决策
reset(config, seed)创建新实验，重置资源、实体与随机源同时保存生成的环境安排
events(after_seq)按序号读取动作结果和内部战斗事件研究者诊断用，不能直接给模型
advance(ticks) / close()逐步推进 / 结束并保存实验；终局见观察的 statusadvance 仅限离线运行及回放

05 · 实验流程

核心原则：真人和 AI 面对同一环境、同一动作空间、同一日志格式。
STEP 1

固定实验条件

  • 选择关卡
  • 固定随机种子
  • 固定植物池
  • 固定环境安排、规则和版本
→
STEP 2

Human / AI 分别试玩

  • 真人：正常鼠标操作
  • AI：公开 Observation → Action
  • 两者均经过统一动作执行器
  • 逐步保存 State / Action / Event
→
STEP 3

行为比较

  • 结果表现
  • 资源与策略分布
  • 状态下动作选择
  • 动作时间线与回放复查

06 · Human–AI 一致性评价框架

已有整局指标和同局面动作一致率；完整轨迹相似度仍是后续研究项，不代表已有实证结论。
结果层 · Outcome
已有：胜负、持续时间、资源收支、植物损失、小推车消耗；超时与技术中断分开
行为层 · Behaviour
已有：布局、动作时间线、AI 延迟与错误；更细的策略比例指标可后续扩展
决策层 · Decision
已有：真人动作前公开局面上的动作类型、植物与位置一致率；等待样本单列
轨迹层 · Trajectory
后续：在现有日志与回放基础上定义轨迹相似度，尚未形成统一评分

注：条形长度仅为研究关注程度示意，不是测量结果或完成度。同局面比较只使用真人动作之前的信息，不输入本次真人动作或后续结果；结构化观察降低了 AI 的识别负担，因此这里只研究策略与决策，不等同于真人视觉体验。

07 · 《植物大战僵尸》实验平台定位

PvZ 是个人研究的实验载体；当前只运行白天草地，不追求复刻全部玩法。
采用

wszqkzqk / pypvz

  • 直接基于 pypvz，沿用其原植物、僵尸与战斗设计
  • 实体已按植物、僵尸、子弹与场地对象分类
  • 全部原素材保留，保留不代表内容已启用
  • Python 易于修改与接入 AI
  • 上游来源与原作者使用声明保留于 docs/UPSTREAM.md
使用方式

白天实验版 V2

  • 三个预设：经济建设、装甲压力、快速突袭
  • 默认六植物、四僵尸；配置示例可加入高坚果与旗帜僵尸
  • 白天 5×9 草地、自动阳光、固定卡组与每行小推车
  • 固定 20ms 时间步、种子生成出怪安排、统一动作与记录
  • 通过参数和注册扩展原有机制，新增内容仍需行为验证

08 · 项目边界

聚焦可控、可调用、可比较的个人实验环境；已有接口不等于研究结论已被验证。

本项目重点

  • 模块化战斗核心与统一实验控制层
  • 公开 Observation / 标准 Action
  • 真人操作语义化记录
  • AI Agent 接入接口
  • 固定条件与可复现实验
  • 行为轨迹日志与回放
  • Human–AI 一致性分析

本项目不重点解决

  • 完整复刻全部 PvZ 内容
  • 追求商业级 UI / 动画效果
  • 从零训练大型 AI 模型
  • 必须使用 VLM 纯视觉操作游戏
  • 一开始就做通用多游戏框架
  • 复杂在线服务；GitHub 托管代码不等于云端运行游戏

获取与使用

代码、素材、配置与文档已上传至 ljr24/let-agents-play-。Windows 下载并解压仓库后，安装 Python 3.12（含 Python Launcher），先双击 setup_day_lab.cmd 联网安装依赖，再双击 start_day_lab.cmd。这是源码版，不是免安装 exe；真人与规则 AI 不需要云端密钥。

文档分为 DEVELOPMENT.md（架构与扩展）、DATA_FORMAT.md（数据与回放）、UPSTREAM.md（来源与使用声明）。开发时的测试脚本和历史测试产物已按要求清理；正常记录、回放与分析功能保留。已上传的源码版没有附带本机环境、密钥或私人对局数据。
