# 白天实验室 V2 使用说明

## 1. 启动与游玩

项目目录：E:\AI_game_test。双击 start_day_lab.cmd，或者运行本地 Python 的 -m daylab。

默认选择真人游玩、经济建设、种子 42。默认规则与 V1 相同：白天 5×9 草地，自动阳光，六植物、四僵尸，六波。初始 150 阳光；自然阳光第 7 秒开始每 7 秒 25 点；向日葵种下 6 秒首次产出，此后每 24 秒 25 点。

三个预设：经济建设、装甲压力、快速突袭。它们是比较与验证用关卡，不宣称已经完成难度平衡。

- 点击卡片，再点草地种植；右键取消。
- 1～6：当前页选卡。超过六张时左右键或滚轮翻页。
- S：铲除，再点植物；不退款。
- Enter：提交等待；终局时返回入口。
- P：暂停/继续，会标记人工干预。
- Esc：结束当前局或退出回放。
- R：仅练习模式可以重开。
- AI 游玩时不能用鼠标接管；滚轮可以查看卡组其他页。
- 界面行列从 1 开始，程序接口从 0 开始。

阳光、冷却、占用和动作频率由同一执行器检查。点击没有成功时看底部原因；选中卡片不代表已经种植。正式实时局的人工暂停或时序异常会使其退出未干预成绩比较。

## 2. 实验配置与扩展内容

“实验配置”留空时，使用上方预设。选择 JSON 后，以文件里的卡组、场景、波次和参数为准；控制者、练习开关和种子仍来自界面。

- configs/expanded_day.json：七张卡，加入原有高坚果；敌人组合包含原有旗帜僵尸。
- configs/pressure_parameters.json：出怪更密集，调整原机制中的射速和部分敌人血量。

这些只是额外实验条件，不替换默认基准。高坚果、旗帜僵尸是本次验证扩展方式的内容；其他植物/僵尸虽然原代码和素材保留，但未全部接入和验证，不能仅凭名称加入配置。

允许调整的字段和范围见 [开发与交接](docs/DEVELOPMENT.md)。每局记录完整配置与实际出怪安排，因此不同参数不会被误认为相同实验条件。

## 3. 记录和比较

每局保存到 experiments/日期时间-编号，结果写在 result.json。记录包含动作、拒绝原因、公开观察、战斗事件、内部检查点，以及云端模式下的请求与回复。记录可能包含模型提供商收到的实际公开输入，请按研究数据管理。

启动菜单可以查看已保存记录，Ctrl 多选后进行比较。正式配对要求相同实验条件、执行模式、代码/依赖/素材版本，并且记录已完整结束且未受干预。技术退出、时限到达和正常战败分别标记。

“同局面比较”只接受真人记录，使用真人动作之前的公开输入询问规则 AI 或云端 AI。真人待比较动作、后续结果和未来出怪不进入模型输入。等待样本单独统计，不能用大量等待提高总体一致率。

结构化观察减少了 AI 的视觉识别负担，报告研究的是策略与决策，不宣称人与 AI 的感知体验完全相同。

## 4. 回放与 V1 旧记录

选择一局，输入秒数，再点回放。空格播放/暂停，左右键跳转 5 秒，+/- 调整回放速度，滚轮翻卡组页。跳转通过从开局快进实现，不是直接恢复任意对象存档。

新版本记录正常检查代码、依赖和素材版本。V1 记录的代码指纹不同，界面会先确认是否进行跨版本检查；即使检查点一致，也会明确显示它不是同版本验证。

```powershell
.\.venv\Scripts\python.exe -B -m daylab replay experiments\某局目录 --verify
.\.venv\Scripts\python.exe -B -m daylab replay experiments\旧版本某局目录 --migration-check
```

保留的真人旧记录没有被改写。原 V1 源码备份已随测试归档移到回收站，当前目录不再提供旧版入口；代码迁移与恢复边界见 [开发与交接](docs/DEVELOPMENT.md#11-原项目到当前结构的对应关系)。

## 5. 云端 AI

云端连接方式沿用第一版，不绑定服务厂商。复制 cloud.example.json 为 cloud.local.json，填写服务地址、模型名和密钥环境变量名称。密钥放在本机环境变量里，不要写进记录或聊天，也不要提交到仓库。

云端模式会把公开观察及近期公开历史发送给配置的服务，可能产生费用；界面会先确认。每局最多一个请求在途，通用默认最短间隔 1 秒、超时 10 秒、观察超过 5 秒作废、最多 300 次请求。错误、延迟、实际 Token 或估算用量会记录；无有效回复时继续等待，不会暗中换成规则 AI。各服务示例可覆盖这些值，以实际配置为准。

兼容 Chat Completions：支持结构化输出时使用严格 schema；否则使用 JSON 输出并在本地验证。token_limit_field 支持 max_completion_tokens 或兼容服务需要的 max_tokens。本次没有更改提供商协议，也没有进行付费调用。真实服务配置和真人/云端配对仍需要另行验收。

DeepSeek Flash：启动界面的“云端配置”选择 `cloud.deepseek.example.json`，密钥由 `PVZ_API_KEY` 环境变量读取。示例现在使用 JSON 输出、`thinking: "enabled"`、`reasoning_effort: "high"`、120 秒总超时和 8192 输出 Token 上限。思考模式可能增加等待与费用，本次未做真实云端验收。通用示例不强行添加厂商专有思考参数。

### 思考暂停与提示词编辑

两个示例默认 `decision_mode: "pause_think"`：请求、纠错和请求间隔等待期间，游戏模拟时间冻结；一次决策结束后，按正常画面速度推进 `advance_after_decision_ms: 1000` 毫秒，再请求下一次决策。每步仍是20毫秒。网络错误或最终非法回复也会在记录后无动作推进，避免同一局面无限重试；调用预算耗尽则以 budget_exhausted 技术结束。网络超时按现实时间计算，观察过期按模拟时间计算，所以正常长时间思考不会令冻结的局面过期。

窗口仍可响应退出和手动暂停；自动思考冻结不记作人为干预，也不补跑等待期间的时间。不使用这套模式与真人实时成绩直接配对。需要原实时模式时设 `decision_mode: "realtime"`；实时模式的旧观察仍会被拒绝，开启思考不会自动放宽合法性检查。

- `prompts/cloud_framework.md`：完整提示词框架，分为目标、规则与空间、风格、时间与记忆、决策流程、输入、输出七层。
- `prompts/play_style.json`：你主要编辑的文件，修改 name 与 instructions。比如 name 改为 aggressive，instructions 改为“优先及时建立火力，愿意牺牲部分经济换取快速清场；不在无法攻击目标的位置盲目投入”。无需修改 Python。
- 云端配置的 `prompt_file`、`style_file` 可指向自己的文件。相对路径基于项目根目录，绝对路径也支持。

框架中的 `${rules}`、`${cards}`、`${style}`、`${timing}`、`${input_format}`、`${output_contract}` 是程序填充接口，请保留这些名字；普通美元符号写成 `$$`。每次加载配置时读取并校验文件，运行中的一局使用内容快照，不热更新。改好后重新加载配置/开始新局。完整框架、风格及 SHA-256 写入 model_config；每次渲染后的实际提示词在 model_requests 中，不同内容会被视为不同控制器配置。

## 6. 开发与检查

输出可靠性：两个云端示例现在采用 `compact_context: false, history_encoding: "board"`。输入是按时间从旧到新排列的文字棋盘，最后明确标记 CURRENT 当前。植物按格展示，僵尸另按行和准确像素坐标列出，允许重叠且不会把屏幕边缘敌人挤进错误格子。当前植物编号、状态、可见子弹、卡片价格/冷却/可用性、小推车都保留；卡片进度小数不重复发送。过去五秒的每秒帧保留布局、敌人、阳光、波次和小推车，省略过去子弹、植物动画及卡片冷却，因此是历史摘要，不是无损编码。已完成动作另列，输出仍是原来的单动作 JSON。

固定规则、图例和价格在前，动态棋盘在后；这不是累积整局聊天，也不保证缓存命中率。旧 `history_encoding: "full" / "delta"` 仍兼容；`compact_context: true` 仅与 full 配合。实际输入记入 `model_requests.jsonl`，原始观察/决策日志不变。自定义配置不会自动改写：如使用自己的 JSON，请将 history_encoding 改为 board，compact_context 改为 false。

单局记忆：两个示例默认开启 `fact_memory: true` 和 `strategy_memory: true`，`memory_max_events: 20` 保留最近二十条重要公开事实，另保留整局类别计数；`strategy_max_chars: 400` 限制策略备忘长度。事实来自公开观察和实际动作结果，植物消失只记“消失”，不猜测原因。策略由模型返回，合法且被接收的回复才更新；它只是意图，不代表动作已执行成功。下一次输入带上记忆和最新棋盘，当前状态优先。新局清空记忆，不跨局共享或自动从旧日志恢复。

启用策略备忘时，模型回复必须为 `{"action":{"type":"WAIT"},"strategy":"当前目标、下一步和调整条件"}`；关闭时保持原来的 action 单字段。记忆及输出预算仍计入原调用预算，未增加自动调用。实际输入和原始回复可审计，策略更新另记 `model_memory.jsonl`。离线同局面测试仍是独立首答样本，不串联其他样本策略，也不冒充具备完整实时记忆的对局。

DeepSeek 示例恢复 `min_interval_s: 1`，启用 `repair_invalid_reply: true`，最多 300 次请求、累计 Token 预算 300 万；纠错请求同样计入预算并受间隔约束。正式比较必须统一控制器配置，不能把不同提示词、输入编码、纠错策略或调用频率当作相同实验条件。

回复分三层检查：严格 JSON/动作格式；依据当时公开观察检查卡片、阳光、冷却、占用和铲除目标；最终由共用执行器在执行时再次检查真实状态。重复 JSON 字段也拒绝。首答格式或观察合法性不通过时，最多发起一次明确纠错，使用新的公开观察；纠错再次失败则该次决策放弃，之后回到正常决策流程。过期、超时、断连及终局不是这种纠错的对象。首答与纠错结果分别保留，不静默替换命令、不伪造成功，也不保证合法动作就是最佳策略。

异常防护：模型动作 JSON 限制大小与嵌套深度；配置拒绝布尔值冒充数字、非整数预算、NaN 和 Infinity。HTTP 在可终止的独立进程中执行，总时限覆盖连接和读取；终局关闭可重复调用，不重复记账。若自定义传输仍卡死，实验标记技术故障结束，不无限积累工作线程。

报告分别列出首答、纠错、提交与执行；终局未采用回复不等于模型错误，也不表示服务端已经取消计费。`已确认Token` 只合计收到的用量，另列用量未知请求，最终账单以服务商为准。严格配对还检查云端配置；不同模型/策略可描述性比较，但不是相同控制器条件。离线同局面比较固定采用一次首答，不启用实时纠错，并在报告元数据明确标注。

动作进入队列后，下一次云端请求等待游戏执行并发布新局面，避免用种植前的阳光、冷却或空格信息连续决策。网络等待期间游戏仍正常推进，因此真正的局面变化仍可能导致最终执行拒绝，这与回复格式错误分开统计。

开发期间的测试脚本和历史测试产物已按要求清理。模块开发说明与后续修改的验证要点见 [开发与交接](docs/DEVELOPMENT.md)；正常游玩仍会产生新的实验记录。具体文件含义见 [数据格式](docs/DATA_FORMAT.md)。

公开 Python 接口由 daylab.GameSession 提供；真人与 AI 共用 submit。不要用修改实体字段的方式实现正式 AI 控制。内部 events() 含精确伤害等研究数据，模型应使用 observe() / public_context()。

保留素材里有 libpng 的颜色配置警告，出现这些警告不等于游戏崩溃。若真的出现异常，请保留控制台错误与对应 experiments 目录，不要先删除记录。
